# MSRV bump 1.85 → 1.88 — design

**Date:** 2026-06-06
**Status:** approved (maintainer picked 1.88 this session; executed same-session)
**Queue:** post-release flexible-queue item 19 (memory: `post-release-msrv-bump`)

## Goal

Raise the project MSRV from 1.85 (the edition-2024 floor, set in WS0/D9) to
**1.88**, and document the bump policy so future raises follow a rule.

## Why now, why 1.88

- **Dep pressure:** `cargo metadata` audit over the resolved tree shows
  `wasip2 v1.0.3` requires **1.87** — the highest requirement today (next:
  hashbrown/indexmap/wit-bindgen at 1.85). First observed 2026-06-03; the
  trend only goes one way.
- **1.88 over 1.87:** stabilizes let-chains for edition 2024 — a real
  ergonomic win for future code — at the cost of five extra weeks of
  toolchain age (Jun 2025; a full year old at bump time, current stable
  1.96).
- **Timing:** before the 6.0.0 final publish, so the published manifests
  advertise 1.88 and the bump rides the already-breaking 6.0.0 line instead
  of forcing a later one ("do them as one move" — queue memory).

Rejected: 1.87 (need-only; forfeits let-chains for no real compatibility
gain), 1.91+ (~stable−5 headroom; more aggressive than a foundational
binding needs today).

## Pinning sites (bumped lock-step, one commit)

1. `rust-toolchain.toml` — `channel = "1.88.0"` + comment explaining the
   floor drivers (deps + let-chains vs the 1.85 edition minimum).
2. `rust-version = "1.88"` in `raylib/Cargo.toml`, `raylib-sys/Cargo.toml`,
   **and `showcase/Cargo.toml`** (the queue memory listed only two — the
   showcase crate also pins).
3. `.github/workflows/check.yml` `msrv` job: `dtolnay/rust-toolchain@1.88.0`
   + `cargo +1.88.0 build -p raylib -p raylib-sys --features full`.
4. Non-gate toolchain pins tracking MSRV: `pages.yml` (1×), `showcase.yml`
   (2×).
5. Docs: `README.md`, `CLAUDE.md` (header + quality-gates line), the four
   book install pages (`Rust 1.88+`).
6. `CHANGELOG.md`: Unreleased → Changed bullet (rationale + policy pointer);
   the 6.0.0-rc.2 block's forward-looking lines flip to 1.88 with a note
   that the rc.2 snapshot itself shipped declaring 1.85. Historical lines
   (e.g. "#290 resolved by MSRV bump to 1.85", WS6 record in `CLAUDE.md`)
   stay untouched.

## Policy (recorded in CLAUDE.md)

The MSRV may rise in minor releases when deps or meaningful language
features demand it, staying roughly a year behind stable. Every bump updates
all pinning sites lock-step (list lives next to the policy).

## Risk: toolchain-jump side effects

Bumping `rust-toolchain.toml` moves dev/CI to 1.88's clippy + rustfmt.
Mitigation: run the verbatim CI gates locally on 1.88 (fmt `--all --check`,
all three clippy `-Dwarnings` legs, nextest, doctests, the msrv build
command) and fix-forward anything that surfaces in the same PR.

## Done criteria

- All gates green locally on 1.88 and on the PR.
- `cargo metadata` audit shows no resolved package requiring > 1.88.
- Policy paragraph in `CLAUDE.md`; CHANGELOG entry; queue item 19 closed.
